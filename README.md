# FastDepth-GD

Reference implementation for **Structure-Aware Knowledge Distillation for Lightweight Monocular Depth Estimation in UAV Nadir Imagery**.

FastDepth-GD trains a MobileNetV2--FPNLite depth estimator using ground-truth depth supervision and offline, per-image scale-calibrated predictions from a frozen ZoeDepth-NK teacher. The teacher is used only to prepare training labels; inference uses the student network alone.

## Repository contents

- `main.py`, `models.py`, `criteria.py`, `Data.py`, `metrics.py`, and `utils.py`: training, model, losses, data loading, and evaluation.
- `teacher/generate_teacher_labels.py`: generate scale-calibrated teacher labels for the training split.
- `ablation_eval.py`: evaluate trained ablation checkpoints.
- `deployment/rk3588/`: ONNX export, ONNX Runtime benchmark, and RKNN conversion utilities.

The implementation builds on the FastDepth project and its published design: [tau-adl/FastDepth](https://github.com/tau-adl/FastDepth), Wofk et al., ICRA 2019. The student uses a MobileNetV2 encoder and a lightweight feature-pyramid decoder.

## Requirements

Use Python 3.9 or newer and a CUDA-enabled PyTorch installation for training. Install a PyTorch/torchvision pair compatible with your CUDA version, then install the remaining packages:

```bash
python -m pip install -r requirements.txt
```

Teacher-label generation loads ZoeDepth-NK using `torch.hub` and therefore requires network access on its first run. The RKNN conversion utility requires Rockchip RKNN Toolkit2 and a compatible host environment; it is optional.

## Dataset layout

The UseGeo dataset and model weights are not redistributed in this repository. Arrange the dataset as follows:

```text
data/
  usegeo/
    train/
      rgb/       # RGB images
      depth/     # matching *_depth_res.tiff ground-truth maps
    val/
      rgb/
      depth/
  teacher_depth/ # generated by the teacher-label script
```

RGB files use names ending in `_res.jpg`; each ground-truth file is expected to use the corresponding `_depth_res.tiff` name. Ground-truth depth and calibrated teacher maps are stored in the dataset's depth units and divided by `--depth-scale` and `--teacher-scale` during loading. The included teacher-label script reads only `train/rgb` and `train/depth`; it does not use validation labels.

## Prepare teacher labels

```bash
python teacher/generate_teacher_labels.py \
  --rgb-dir data/usegeo/train/rgb \
  --depth-dir data/usegeo/train/depth \
  --output-dir data/teacher_depth
```

For each training image, the script predicts ZoeDepth-NK depth, resizes it to the ground-truth dimensions, and multiplies it by the ratio between the valid-pixel medians of ground truth and teacher prediction. Missing ground-truth pairs cause an error rather than falling back to a dataset-wide scale.

## Train

The following command uses the two-stage training schedule reported in the paper (512 x 768 followed by 768 x 1152 from epoch 31):

```bash
python main.py \
  --data usegeo --arch MobileNet --decoder fpnlite \
  --input-height 512 --input-width 768 --batch-size 8 --epochs 50 \
  --lr 1e-4 --depth-scale 100 --teacher-scale 100 \
  --teacher-path data/teacher_depth \
  --distill-gamma 0.01 --distill-multiscale-lambda 0.02 \
  --distill-warmup-epochs 5 --aux-lambda 0.1 --edge-lambda 0.1 \
  --silog-lambda 0 --teacher-edge-lambda 0.1 \
  --ssim-lambda 0.05 --grad-gt-lambda 0.05 --max-grad-norm 0.5 \
  --finetune-height 768 --finetune-width 1152 --stage2-start-epoch 31 \
  --use-guided-upsample
```

Add `--disable-ca` to train the No-CoordAtt variant. Checkpoints and logs are written under `results/`. The training entry point currently expects CUDA and calls `.cuda()` directly.

## Evaluate ablations

Train the variants with the corresponding loss switches and `--ablation-tag`, then update the checkpoint paths in `ABLATION_VARIANTS` near the top of `ablation_eval.py` to match the output directories. Run:

```bash
python ablation_eval.py --input-height 512 --input-width 768
```

The evaluation script reports metrics on the validation split without post-hoc scale alignment.

## Export and deployment

Export a trained checkpoint to ONNX:

```bash
python deployment/rk3588/export_fastdepth_onnx.py \
  --checkpoint results/<run>/model_best.pth.tar \
  --output results/fastdepth_512x768.onnx \
  --decoder fpnlite --height 512 --width 768
```

For an ONNX Runtime benchmark, install `onnxruntime` and run:

```bash
python deployment/rk3588/benchmark_onnxruntime.py \
  --model results/fastdepth_512x768.onnx --height 512 --width 768
```

RKNN conversion is hardware- and toolkit-version-dependent; see the command-line options in `deployment/rk3588/convert_to_rknn.py`.
